# Stack pack: Django + Django Ninja (Extra)

Pack sections are appended by different pipelines; each owns its own heading.

## Security surfaces

Lead with these when hunting in a Django Ninja codebase. For each, read the real wiring before flagging: framework defaults and base classes often supply the check.

- **Authentication on controllers.** Check `auth=` at `@api_controller` level and per `@route`. A route-level `auth=None` or a class without `auth` on a controller that serves private data is a finding; optional-auth (anonymous allowed) routes need their handlers checked for privileged branches. Confirm the auth class validates expiry and token type (an access token versus a refresh or password-reset token).
- **Permission classes.** Find where permissions are attached (controller `permissions=[...]`, route-level, or manual checks). `get_object_or_exception()` in Ninja Extra runs `check_object_permissions()`, so a bare model lookup is authorized by an attached object permission class; do not flag an unscoped queryset when one is attached, and do flag the reverse: `Model.objects.get(pk=...)` or `get_object_or_404` with no object permission and no scoping filter.
- **Object scoping.** `get_object_or_404(Model, id=id)` without the tenant, owner or visibility filter is BOLA. Check every path parameter and every id in the request body (foreign keys in payloads are caller-controlled and must be checked against the caller's scope, not just existence). Check list endpoints, search, filters (`FilterSchema` fields that reach `.filter()` with user-chosen lookups), ordering parameters and exports.
- **Schema field exposure.** `ModelSchema` with `fields = "__all__"`, a long `fields` list, or `exclude` exposes new columns automatically; read what the model has. Nested schemas inherit exposure: a safe parent embedding a user, organization or payment schema leaks whatever the child exposes. Check whether the same child schema is reused for owner-only and public responses. Check input schemas for privileged fields (role, owner, status, fee, verified flags); with `model_dump(exclude_unset=True)` plus `setattr` loops a PATCH can set anything the schema declares.
- **Mass assignment via model_dump.** `Model(**payload.model_dump())` and `setattr(obj, k, v)` over dumped payloads: every declared field is writable; confirm none is privileged.
- **Transactions and on_commit.** With `ATOMIC_REQUESTS`, an `HttpError` raised inside the view does not roll back unless an inner `transaction.atomic` boundary exists; side effects (emails, tasks, payment calls) run before the error and are not undone. `transaction.on_commit` callbacks never run in a rolled-back transaction, and tasks dispatched outside it can run before the row is visible. Look for check-then-act sequences split across the boundary.
- **Locking.** Read-modify-write on counters, capacity, balances or single-use tokens needs `select_for_update` (inside `atomic`), an `F()` expression, or a unique constraint. `get_or_create` without a unique constraint is racy. `select_for_update` on a queryset that is later re-fetched, or applied after the read, protects nothing. Pgbouncer or server-side cursors with `.iterator()` are a reliability issue, not a vulnerability.
- **Bypass paths around service checks.** Rules enforced in a service or `clean()` are skipped by `QuerySet.update()`, `bulk_create`, `bulk_update`, raw SQL, `save(update_fields=...)` paths that avoid `full_clean`, fixtures and management commands. Check Django signals (`post_save` handlers that grant access or send mail), admin actions and admin forms (staff-only does not mean the invariant is safe; admin can often create states the API forbids and trigger signals), and sibling API routes for other roles that reach the same model.
- **Celery task inputs.** Tasks receive ids or payloads that may have been attacker-influenced at enqueue time; check the task re-validates ownership and state, does not trust serialized objects, and does not log arguments containing tokens or personal data. A task pinned by name must keep its name; a task that renders email must set the recipient's language explicitly (workers have no active language).
- **File storage and serving.** `FileField`/`ImageField` upload paths built from user input; stored extension or user-supplied content type driving the served `Content-Type`; user uploads served inline from the application origin (stored XSS via SVG or HTML); public versus protected storage for private files; scan or quarantine state not enforced on serve; `X-Accel`/redirect-style serving without path checks.
- **Throttling and pagination.** Mutation routes without a write throttle; unbounded `page_size`; expensive endpoints (search, export, external API, LLM) without limits; throttle keys derived from spoofable forwarded headers (check the proxy count setting).
- **Settings and wiring.** `DEBUG`, `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS`, CORS allow-all with credentials, cookie flags, `SECRET_KEY` fallbacks, `SECURE_PROXY_SSL_HEADER` trust, `USE_X_FORWARDED_HOST`; error handlers that leak exception text; exception handlers registered per app and which exceptions map to which status.
- **Raw SQL and dynamic lookups.** `.extra()`, `RawSQL`, `.raw()`, `cursor.execute` with f-strings, `order_by` or `values()` from request data, `annotate` with user-chosen expressions.

Typical non-findings: an object permission class attached at controller level; `UUID` ids in errors the client needs; permissions that do exactly what their name says.

## Debt conventions

Hunters and verifiers use this section as the house pattern to measure drift against. A pattern the repo's CLAUDE.md documents as intentional is not debt.

- Thin controllers: business logic (multi-step flows, rollback, domain rules, VAT or pricing checks) belongs in services; controllers parse input, authorize, call a service, return. Flag controllers with branching domain logic, direct multi-model writes, or try/except where an app-level exception handler mapping exists.
- Dependency direction is controllers, services, models/utils. Models never import services; pure model helpers live in a per-app `utils/`. A function-local import in a model or util that points at a service is a cycle held by a local import.
- Hybrid service style (function-based for stateless operations, class-based for request-scoped multi-step workflows) is by design, not inconsistency.
- Schema hygiene: ModelSchema declares fields only when they need special handling; enum fields reference the model's enum class, not bare `str`; datetimes use `AwareDatetime`; new schemas are re-exported from the package `__init__` (import and `__all__`) so type checking resolves them. Optional JSON bodies use `Annotated[..., Body(None)]`; Query/Body params use the `Annotated` idiom rather than type-ignores.
- Celery: every task pins `name=` explicitly (default names derive from the module path and break beat rows and in-flight messages when moved). Tasks dispatched from a request go through `transaction.on_commit` when the request is atomic; tasks let exceptions propagate instead of swallowing them. Beat jobs respect the repo's cadence rule. A per-minute job is debt unless genuinely cheap.
- Migrations: one schema migration per app per PR, squashed by regenerating (never hand-edited); data migrations and beat-task rows stay separate; data migrations use `apps.get_model`, not live models. Count migrations per app as a metric; unclaimed schema-only runs are squash candidates.
- Queries: N+1 (loops that touch a relation without `select_related` or `prefetch_related`), `.distinct()` on wide joins, `.iterator()` behind a connection pooler, counting with `len(qs)`, queries inside serializers or schema resolvers. Paginated list endpoints should have a query-count test that would fail if an N+1 appeared; a test whose count block wraps no queries is a test smell.
- Error handling: per-app exception-handler maps instead of try/except in controllers; `get_object_or_404` instead of catching DoesNotExist; no string matching on exception messages; user-facing messages marked for translation when the repo enforces it.
- Admin and config: an admin module not wired into a curated sidebar is invisible; settings split by concern; dead settings need a search of installed packages before they are called unused (libraries read settings by name).
- Typing and style signals: `from typing import` where the house style is `import typing as t`, untyped signatures under strict mypy, `type: ignore` without a code or reason, raw dicts where a TypedDict, Pydantic model or dataclass fits.
- Dead-code oracles: the generated OpenAPI artifact lists every live schema component; Celery tasks with no `.delay` or `.apply_async` may still be scheduled by name in beat data migrations; signal receivers and aliased task imports defeat plain greps.
